Rules for re-running the Phase 3 real-corpus evaluation after adding the two WHO hand hygiene documents.
Written and committed BEFORE any query was run on the five-document corpus.

Why: the real corpus grew from 3 to 5 documents (adds the 2009 WHO hand hygiene summary and the 2026 WHO IPC newsletter).
The earlier real-corpus numbers (tag final_3doc) describe the 3-document corpus only.

1. Frozen configuration. No change to retriever weights, validator, generator code, prompt or threshold (0.6) in this run.
2. One loader fix is included, made before any query was run: ligature characters (fi, fl, ffi) and "/gNNN" glyph placeholders
   in extracted PDF text are normalised. They occur only in the hand hygiene PDF; the other PDFs contain none, so their chunks must
   be unchanged (checked before the run).
3. 17 new queries (15 in-corpus, 2 out-of-corpus) were written from the PDF text before any run. Existing queries are untouched.
   New dev = R18 R20 R22 R24 R26 R28 R30 RO5; new test = R19 R21 R23 R25 R27 R29 R31 R32 RO6.
4. Order: dev (both generators) first, then test once per generator. Every test run is logged in test_split_runs.log. The 10
   original real test queries are being run a second time; the report shows them separately from the new ones.
5. Nothing is tuned from these results. Problems found (for example reference-list noise chunks) are reported as limitations,
   not fixed in this run; a fix would need a new accept rule and fresh queries.
6. Results are reported whatever they are, including any criterion that was met before and is not met now.

ADDENDUM (still before any query was run on the five-document corpus)
The label check (check_labels.py) rejected R28 and R29: their expected phrases were in section titles, not chunk text. Cause: the
PDF heading detector took wrapped lettered recommendations ("A. The use of gloves does not replace the need for hand / hygiene by...")
as headings. Fix: a line followed by a lowercase-initial line is a wrapped sentence, not a heading. This is a loader defect fix,
not a tuning step; it was found by the label check, not by a result. It also moves a few chunks in the three original PDFs, so
rule 2's expectation that they are unchanged no longer holds for them. The per-document effect is measured by
evaluation/loader_fix_effect.py and saved in reports/loader_fix_effect.json. Consequence for reading the results: the change from
the 3-document to the 5-document real results mixes two causes (added documents, loader fixes); it cannot be separated without a
third run, and that run is not done.
