# GuideRail

A citation-first RAG assistant for healthcare guideline documents (WHO, CDC, NIH style), built for Spinnaker Analytics.
It answers **only** from retrieved guideline text, checks every answer against that evidence, and returns
`needs_review` instead of guessing when the support is weak.

- **Deterministic indexing, no API needed.** 256-D hashed n-gram embeddings feed a FAISS index; two builds give identical hashes.
- **Two generators.** An extractive one (no model, the default) and an optional Claude one that is told to use the evidence only.
- **An independent validator.** Confidence is evidence coverage times relevance. Below the threshold (default 0.6) the status is `needs_review`.
- **Version policy.** Superseded guideline versions are excluded from answers by default.
- **Evaluated on held-out queries**, on a synthetic corpus and on real WHO and CDC PDFs, with the limits reported.

## Quick start

Requires Python 3.12. Use a virtual environment **outside any cloud-synced folder** (see the RUNBOOK).

```bash
python3 -m venv .venv && source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python scripts/pipeline.py --check-determinism              # build ./index from data/guidelines and verify reproducibility
uvicorn guiderail.api:app --app-dir src --port 9070         # serve the API
```

Ask a question:

```bash
curl -s localhost:9070/qa -H 'content-type: application/json' \
  -d '{"question": "How long should alcohol-based hand rub be applied?", "top_k": 5}'
```

The response always has this shape (`?debug=true` adds validator details):

```json
{ "answer": "string",
  "citations": [ { "chunk_id": "", "doc_id": "", "title": "", "agency": "", "year": 0, "version": 0, "section": "", "score": 0.0 } ],
  "confidence": 0.0,
  "status": "validated | needs_review" }
```

`GET /health` reports the index hash, counts, generator and threshold. Interactive docs are at `/docs`.

## Streamlit UI

```bash
streamlit run ui/app.py        # talks to the API at GUIDERAIL_API_URL (default http://localhost:9070)
```

## Docker

```bash
docker compose up --build      # API on :9070, UI on :8501
```

The Docker files were written but **not run** on the machine this was built on (Docker was not installed there).
See the RUNBOOK before depending on them.

## Using real documents and the LLM generator

See [docs/RUNBOOK.md](docs/RUNBOOK.md): registering PDFs in `data/real/sources.json`, building the real index, switching to
`GUIDERAIL_GENERATOR=llm`, and swapping in a secure guideline repository through the loader interface.

## Repository layout

| Path | Contents |
|---|---|
| `src/guiderail/` | the package: loaders, chunker, embeddings, FAISS index, retriever, generators, validator, service, API, evaluation kit |
| `data/guidelines/` | the synthetic corpus (Markdown with front matter) |
| `data/real/` | real PDFs and `sources.json` (the PDFs themselves are not committed) |
| `evaluation/` | labeled queries, the evaluation runner, reports and logs |
| `scripts/` | `pipeline.py` (build the index), `check_docs_sync.py`, `live_llm_check.py` |
| `ui/` | the Streamlit client |
| `tests/` | the test suite |
| `docs/` | architecture, runbook, evaluation report and log, development notes |
