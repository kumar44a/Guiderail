_Generated by `evaluation/build_summary.py` from `evaluation/reports/*_final.json`. Do not edit by hand._

## 1. What was measured and how

- Two corpora: 22 synthetic guidelines (79 chunks) and 5 real PDFs from CDC and WHO (1938 chunks).
- Labeled queries per corpus, split into **dev** (used to choose changes) and **test** (held out; run after the configuration was frozen; 6 runs are recorded in `evaluation/reports/test_split_runs.log`). The real corpus was evaluated twice: first on 3 documents, then on 5 after the WHO hand hygiene documents were added (section 9). The tables below are the 5-document run.
- An in-corpus answer is **correct** when it contains every expected fact (stem-aware match) and no value from a superseded version.
- Out-of-corpus queries should be sent to review; an out-of-corpus query that is validated is a **false accept**.
- Two generators: **extractive** (no model, default) and **LLM** (Claude, evidence-only prompt). Both use the same retriever and the same validator.
- Threshold 0.6 throughout (the brief's default). The LLM rows come from live API calls and vary slightly between runs.
- Samples are small. Percentages in parentheses are 95% Wilson intervals; read them before comparing rows.

**Reading the criteria honestly.** A high pass rate is easy to reach and says little: an extractive answer is copied from the evidence, so the share of validated answers is high by construction. What matters is *validated precision* (how many validated answers are actually correct) and how many out-of-corpus questions are wrongly accepted. Raw Precision@5 is capped by corpus structure, because most synthetic documents have only 3 or 4 chunks, so a query with one relevant document cannot score above about 60%. The capped figure divides by the best attainable score.

## 8. Limitations

- **Lexical matching.** Embeddings and validation work on shared words, not meaning. Paraphrases, synonyms ("flu" for "influenza", "bleach" for "sodium hypochlorite") and swapped values that reuse words from the evidence can slip through or be wrongly flagged.
- **Near-domain out-of-scope questions.** The extractive path can answer a question about, say, radioactive waste with on-topic sentences about ordinary waste and validate it. The LLM path abstains far more reliably.
- **Real documents.** With extracted PDF text, the extractive generator is much less reliable than on the synthetic corpus: many of its validated answers are wrong. The LLM generator is more precise and abstains on out-of-scope questions, but at 0.6 it withholds a large share of correct answers (see the pass and correct-but-flagged columns in section 4).
- **PDF extraction noise.** Reference-list pages become noise chunks. Text inside figures (for example the handrub duration diagram) is jumbled. Some pages are image-only and yield no text. These were reported, not fixed, in the 5-document run.
- **Small samples.** The splits have 16 to 20 in-corpus queries each. Differences of one or two queries are noise.
- **Dev reuse and test exposure.** Dev queries chose the changes, so dev numbers are optimistic. The synthetic test split was run once after freezing. The original real test queries were run twice (3-document corpus, then 5-document corpus); the new in-corpus real test queries were run once. The new queries were written by the same author who read the PDF text.
- **Mixed causes in the 3-to-5 document change.** The 5-document run adds documents and also includes two PDF-loader fixes made before any query was run (section 9). Their effects cannot be separated without another run.
- **Prior exposure.** A handful of ad hoc questions were tried on the synthetic corpus before the labeled sets were written, and the validator stress set uses the facts (not the wording) of a few test-split queries to place the true evidence.
- **LLM variance.** Live LLM runs are not deterministic; two dev runs with identical settings differed by a query or two.
- **Scorer.** Correctness is a fact-string check, a proxy for a clinician's judgement.
